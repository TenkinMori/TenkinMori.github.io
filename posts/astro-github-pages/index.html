用 Astro 和 GitHub Pages 搭一个免费博客

2026年11月8日3 分钟阅读教程Astro博客

这个站就是按下面的流程搭起来的。整套东西不花一分钱，也不需要服务器。

为什么是静态站

博客的内容在写的时候就已经确定了，不需要每次访问都去查数据库。既然如此，不如在构建时就把 HTML 全部生成好，直接扔给 CDN。

好处很直接：

  • 快，没有服务端渲染的等待
  • 便宜，GitHub Pages 免费
  • 安全，没有后台就没有后台漏洞

代价是不能跑服务端代码。评论、统计这些，得靠第三方服务在前端解决。

一、建仓库

如果想用 https://你的用户名.github.io 这个地址，仓库名必须是 你的用户名.github.io，并且是公开仓库。

项目页也可以，地址会变成 https://你的用户名.github.io/仓库名/，只是路径里多一层。

二、本地跑起来

npm create astro@latest my-blog
cd my-blog
npm install
npm run dev

Astro 的目录结构很直观：

src/
  pages/        # 每个文件就是一个页面
  content/posts # 文章，Markdown
  layouts/      # 页面骨架
  components/   # 组件

文章就是一个带 frontmatter 的 Markdown 文件：

---
title: 标题
description: 摘要
pubDate: 2026-11-08
tags: ['教程']
---

正文……

三、配置站点地址

在 astro.config.mjs 里写死最终地址，RSS 和 sitemap 都依赖它：

export default defineConfig({
  site: 'https://你的用户名.github.io',
});

四、用 Actions 自动部署

在仓库里新建 .github/workflows/deploy.yml：

name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4

然后去仓库的 Settings → Pages，把 Source 改成 GitHub Actions。

之后每次 git push，Actions 会自动构建并发布，通常一两分钟就能看到更新。

五、自定义域名

有域名的话，在 Pages 设置里填上，然后去域名服务商加一条 CNAME 记录指向 你的用户名.github.io。等 DNS 生效，勾选 Enforce HTTPS 就行。

几个坑

  • 路径大小写：GitHub Pages 区分大小写，本地能跑不代表线上能跑，图片路径尤其注意。
  • 构建失败：Actions 里看不到本地文件的话，通常是 .gitignore 把 dist/ 或图片目录忽略了。
  • 国内访问：*.github.io 不太稳定。绑定自己的域名会好一些，再套一层 Cloudflare 更稳。
  • 免费额度：仓库和站点各 1 GB 左右，每月 100 GB 流量，个人博客基本用不完。

最后

搭站本身只是一下午的事，难的是持续写。所以别在工具上纠结太久——能写、能发、看着舒服，就够了。
